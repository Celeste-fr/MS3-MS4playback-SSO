# Playability checker, built in

Branch `playability-checker` (started 2026-09-27). The owner: "deprecate this plugin and fully
integrate it into the 3.7 fork". The plugin (`~/MuseScore/orchestration-checker`, MuseScore 3.6
QML, sourcebook of textbook references in `data/tables.py`) is frozen from now on; this is its
successor. Its rules, limits and references carry over unchanged unless noted; the plugin's
headless test scores and their checked results are the parity tests.

## What changes by being built in

- **Nothing is written to the score.** The plugin coloured noteheads (or drew symbols over them)
  outside the undo stack; here the colours are decided when a note is drawn (`Note::draw`, like
  MuseScore's own out-of-range colours), from results kept beside the score. Files stay exactly as
  MuseScore 3.6 reads and writes them (the fork's round-trip rule), and printing / PDF export show
  no marks.
- **No copy reader.** Slurs, staccato dots, hairpins, tremolos and harmonic circles are read from the
  score directly (the plugin wrote a copy of the file to find them).
- **Microtones** come from `ScoreTuning` directly (the plugin read `Note.microtonalTuning`).
- **Open strings**: their mark can be switched off, and its look is the owner's choice (page
  "Open String Colour", https://claude.ai/artifact/YYwpUqGSMdLLvByhShbEbj: colours, or a small 0 /
  a ring instead of a colour, which only a built-in checker can draw).
- Speed: a whole-score pass in C++ is expected in milliseconds, so the checker re-runs after each
  edit (debounced) without the plugin's ranged passes and caches.

## Order of work

1. Rules and the pass for stops, open strings, microtones, harmonics, div./unis.; marks drawn;
   preferences; `tst_playability` against the plugin's results on its test scores.
2. Bowing: slur timing (S11), jeté and slurred staccato (S10), fingered
   tremolo (S13), section vs single player.
3. The panel: table, sorting (bar, then staff), marks column, row → blue range box, score → row,
   Selected line with spelling and microtones.
4. Diagrams: fingerboard and harmonic board, wind register graph with its chips.
5. A Windows build for the owner; the plugin's README says where it went.

## Plugin frozen (2026-10-06)

The owner: "stop maintaining the plugin". Nothing in this branch needs it any more:

- `tools/playability/gen_winds.py` reads the sourcebook (`~/MuseScore/orchestration-checker/data/tables.py`,
  local and private because it quotes the books) and does the instrument mapping and transposing
  itself, checked against this repository's `share/instruments/instruments.xml`. The header it
  wrote on the switch was identical, data for data, to the one made through the plugin's winds.js.
- `wind-layouts.json` (the wind graph references) was the plugin's output. After a deliberate
  change to the wind data or drawing, rewrite it from this build:
  `PLAYABILITY_WRITE_WIND_REFS=1 ./tst_playability windLayouts`, then read the diff.
- The plugin's string references (fingerboard, rows) are frozen as they are; any change to that
  behaviour from now on is a fork-only change and updates those files by hand.


## False alarms found by a sweep of real scores (2026-10-13)

A sweep of 15 real scores (public domain, CC0 and CC BY-SA, `~/MuseScore/orchestration-checker/research/false-alarm-sweep.md`)
gave these fixes; tests `falseAlarms` (falsealarm-strings/-keys/-bars.mscx from `tools/playability/gen_falsealarm_tests.py`).
- Tempo: the last tempo text at a tick wins, as `TempoMap::setTempo` plays it (the checker kept the first).
- The Bar column is the measure's displayed number (`Measure::no() + 1`: pickups and measures excluded from the count do
  not shift it; a section break that restarts the numbering restarts it here too).
- Row staff names are plain text (`plainText(...).simplified()`) everywhere.
- The result's counts (`impossible`, `outOfReach`, `notation`) are made from the rows by verdict at the end of the pass,
  as the panel's summary line counts them, so no kind of row (the slur rows were missing) is left out.
- S11: a slur over chords that carry a tremolo is not timed (the slur marks the tremolo), nor is a slur with one note
  (its ties followed) that alone lasts longer than the longest bow at its dynamic (a phrase slur).
- N1: a repeated technique text in parentheses, or with no note since the first text, is not marked.
- Section vs single player (owner 2026-10-13): besides plural names, a string staff is a section when the score is
  laid out as an orchestra (it has a double bass, or a wind or brass instrument), unless its name says solo / soli.
  String quartets and trios keep singular names as single players.
- Left as they were (owner decisions pending): the x0.6 bow factor of cello and bass, an accent dynamic (fz) as an
  entrance dynamic, the one-dot rule of slurred staccato.
